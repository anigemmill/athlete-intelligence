# Live Pipeline Verification — M12 (ResultsAgent) — 2026-08-09

Twelfth live run against the same five golden athletes, real Perplexity + real GPT-4o, after extracting ResultsAgent from the monolith. Compared against the M11 run (`docs/live-pipeline-verification-2026-08-09-m11-intelligence.md`).

## What changed (M12)

**ResultsAgent** (`results-agent.ts`), per docs/roadmap.md / docs/ai-architecture.md ("ResultsAgent — rank/PB/SB with sport-aware cross-validation"). This is the final item on the approved roadmap: the last content still generated by the original monolithic prompt in `auto-populate.ts` (`worldRank`, `worldRankDelta`, `nationalRank`, `personalBest`, `seasonBest`) is now its own dedicated research+extraction module, matching the shape of every other agent (M4–M11). PB/SB cross-validation is unchanged — `crossValidatePerformanceMarks()` in `performance-marks.ts` (M3.1) is still the single implementation; ResultsAgent just calls it instead of `auto-populate.ts` calling it inline.

**A deliberate behavioral fix made alongside the extraction, not silently:** the old monolithic research call threw `PerplexityResearchError` on failure, which aborted the *entire* pipeline — discarding every other agent's already-validated, already-written-ready results (contacts, timeline, competitions, sponsorships, social, biography, photo, intelligence items) just because the rank/PB/SB research specifically failed. That made sense when one shared research call fed everything; it stopped making sense once seven other agents already had their own independent, never-throws research. ResultsAgent was built to match the same contract every other agent already follows — catches its own failures, logs, and returns an all-null/zero default — so a failure in this one agent's research now only means "no rank/PB/SB update this run," not "nothing gets written for this athlete at all." This directly matches the documented target orchestrator shape ("Orchestrator (Promise.allSettled)" in both `docs/ai-architecture.md` and `docs/roadmap.md`) — with every agent now catching its own errors, nothing in the Phase 1 `Promise.all` can reject anymore in practice, achieving the same effect without needing `allSettled` specifically. The now-dead `PerplexityResearchError` class and its special-cased catch branch were removed; `auto-populate.ts`'s catch block now only handles genuine unexpected failures (e.g. a database write failing after all agents already produced results). **Note per CLAUDE.md's AI philosophy ("never store fabricated data"):** this change does not weaken that guarantee — each agent still independently refuses to fabricate its own field on failure (ResultsAgent returns null/0, not a guessed rank or mark); it only stops one agent's failure from discarding *other* agents' independently-verified real data.

`auto-populate.ts`'s shared prompt is now gone entirely — `SYSTEM_PROMPT`/`USER_PROMPT`/`researchAthleteWithPerplexity` all removed. The file now contains only orchestration (the Phase 1/Phase 2 `Promise.all`s, the five DB-write sections) plus `discoverAthleteProfile` (name→identity resolution, a separate concern, unchanged) and `repopulateAthlete`. `CLAUDE.md`'s error-handling guidance was updated to describe the now-uniform "agents catch their own failures and return safe defaults" pattern in place of the removed `PerplexityResearchError` example, which no longer exists anywhere in the codebase.

This is by design from M7; it simply hadn't surfaced in a live-verification run's data before now by chance (M7–M11's reports all happened to sample sponsorships young enough to stay ≥70 after decay). Not caused by, or in scope for, this milestone's extraction.
